Give those steps rewards of −2, 0 and +10. We invented this trajectory, but the difficulty is real: which actions should become more likely? The placement worked. The collision was expensive. Somehow we have to turn both observations into changes to the same policy.</p><p>I like this example because a successful ending leaves so much unresolved. What deserves credit, what counts as good, and how much should we change?</p><div class="rc-mark" data-panel="push" data-view="push" data-title="A signed score for an action"></div><h2 id="sec-push">Turn an outcome into an update</h2><p>Our policy gives action probabilities, written πθ(a|s). The parameters θ are the knobs we adjust. For a sampled action, the gradient ∇θ log πθ(a|s) gives a local direction that increases its log probability.</p><p>Multiply that direction by an outcome score. Positive scores encourage the action; negative scores discourage it; zero contributes nothing. Larger magnitudes make larger contributions. The same network chooses all three actions, so encouraging placement can also change how it reaches and carries. The board starts with REINFORCE’s simple choice: score every action with the trajectory’s total reward.</p><div class="rc-mark" data-panel="credit" data-view="credit" data-title="Keep only future rewards"></div><h2 id="sec-past-credit">Stop charging carry for the collision</h2><p>Our total is 8, so every action initially receives weight 8. But why should carrying inherit a penalty that happened before it? Carry cannot reach backward and undo the collision.</p><p>Use the rewards from each action onward, called <em>reward-to-go</em>. The second panel keeps the collision in reach’s score and removes it from the later scores. This preserves the expected gradient while removing irrelevant sampling noise. The remaining return is still noisy.</p><p>Why can we drop that penalty? The policy’s score gradient averages to zero: E[∇θ log πθ(a|s)] = 0. The action probabilities sum to 1, whose derivative is zero. By the time we choose carry, the collision penalty is fixed at −2. Multiply that fixed number by a gradient whose average is zero, and its average contribution is still zero.</p><details><summary>The zero-mean identity</summary><p>For a discrete policy, E[∇θ log πθ(a|s)] = Σₐ πθ(a|s)∇θ log πθ(a|s) = Σₐ ∇θπθ(a|s) = ∇θ1 = 0. This assumes normalized, differentiable probabilities, valid interchange of differentiation and summation, and logs evaluated only for actions with positive probability. The past-reward argument conditions on the history before the current action.</p></details><div class="rc-mark" data-panel="baseline" data-view="baseline" data-title="Measure performance relative to the start"></div><h2 id="sec-baseline">A failure should look worse than expected</h2><p>Now repeat the placement from the same start. Three attempts earn 10; one earns 0. The failed attempt’s raw zero gives no direct discouraging contribution. That feels wasteful: we have just seen three better outcomes.</p><p>Subtract what we expected from this state. The resulting score is an <em>advantage</em>: how much better or worse the outcome was than expected. The board centers the four returns around their mean.</p><p>A state baseline independent of the sampled action leaves the expected gradient unchanged, by the same zero-mean identity. A poor baseline can increase variance. Our sample mean needs a qualification: if the four attempts are independent draws from the same policy and starting state, using their shared mean shrinks the expected update to 3/4 of the update without a baseline. Comparing each attempt with the mean of the other three avoids that shrinkage.</p><p>We can instead learn the expected return V(s), called a critic. If it predicts 12 and we get 10, a successful placement receives advantage −2. <a href="/robotics/rl-2-bootstrapping/#sec-gae">GAE</a> also inherits errors in learned values, including <a href="/robotics/rl-2-bootstrapping/#sec-time-limits">incorrect time-limit handling</a>.</p><div class="rc-mark" data-panel="clip" data-view="clip" data-title="Clipping depends on the advantage sign"></div><h2 id="sec-ppo">Reuse the attempts carefully</h2><p>Collecting attempts costs something, so we would like several training passes over one batch. Each pass changes the policy, leaving us with actions sampled by an older version.</p><p>The <a href="/robotics/rl-4-on-policy-and-off-policy/#sec-action-correction">probability ratio</a> compares current and collecting probabilities for the sampled action; the denominator must be positive. If that action is now twice as likely, multiplying by the ratio doubles its advantage contribution. The batch still contains states visited by the old policy. This multiplication cannot turn it into fresh attempts from the new one.</p><p>Repeated maximization can keep increasing a positively scored action’s probability. <a href="https://arxiv.org/abs/1707.06347">PPO</a> limits that incentive. Take advantage +2: raising the ratio from 1 to 1.2 raises the objective from 2 to 2.4. Raise it again to 1.3 and the clipped objective stays at 2.4. This sample has stopped rewarding further increases. The board’s negative-advantage curve reverses the direction; both curves retain a corrective slope when probability moves the wrong way.</p><p>The interval [0.8, 1.2] clips an expression; actual ratios can cross it as other samples and loss terms move shared weights. We still choose the learning rate and number of passes. KL divergence measures how far the updated action distribution has moved from the collecting policy; stopping passes when it grows too large adds another control. An entropy bonus encourages exploration separately, outside clipping.</p><div class="rc-mark" data-panel="groups" data-view="groups" data-title="Get the comparison from repeated attempts"></div><h2 id="sec-groups">Let the attempts compare themselves</h2><p><a href="https://arxiv.org/abs/2402.03300">GRPO</a>, introduced for language models, samples a group under the same initial condition, subtracts its mean reward, and divides by its reward standard deviation. It uses these comparisons in PPO’s clipped objective, replacing a separately trained critic.</p><p>Keep our placement task, but switch to binary rewards: placement earns 1, everything else 0. The board works through one success among four attempts. Make all four succeed, or all four fail, and every centered reward becomes zero. With a denominator stabilizer, every task advantage is zero too.</p><p>The weights can still change: GRPO also penalizes moving away from a fixed reference policy. That penalty supplies a separate regularization signal, even with identical rewards. Its fixed reference serves a different purpose from PPO’s monitoring against the collecting policy.</p><div class="rc-mark" data-panel="costs" data-view="costs" data-title="Reward diversity has a collection cost"></div><h2 id="sec-costs">Decide what to collect next</h2><p>Four successes suggest an easy start with little remaining task improvement. Four failures leave us without a successful comparison: an <a href="/robotics/rl-1-q-learning/#sec-bandit">exploration problem</a>.</p><p><a href="https://arxiv.org/abs/2503.14476">DAPO</a> collects extra groups, discards all-correct and all-incorrect groups, and continues until enough informative groups remain. Collection cost varies. On a physical robot, extra attempts would mean extra executions and resets; that extension is untested. DAPO also removes GRPO’s reference KL penalty.</p><p>Dividing by reward standard deviation changes how strongly different groups affect training. <a href="https://arxiv.org/abs/2503.20783">Dr. GRPO</a> removes that division and, in its language-model setting, division by response length. Both changes address biases introduced by those normalizations. Identical rewards still leave zero centered scores.</p><p>What should we change before the next batch? If every attempt fails, we need to find a successful placement to compare against. If action probabilities keep changing too much during training, take smaller steps or make fewer passes over the batch.</p><footer><p><a href="/robotics/rl-5-the-deadly-triad/">Previous: the deadly triad</a> · <a href="/robotics/rl-0-overview/#sec-failures">Series failure map</a> · <a href="/robotics/rl-7-learning-from-fixed-data/">Next: learning from fixed data</a></p><p>Further reading: <a href="https://spinningup.openai.com/en/latest/spinningup/rl_intro3.html#don-t-let-the-past-distract-you">reward-to-go derivation</a>; <a href="http://incompleteideas.net/book/RLbook2020.pdf">Sutton and Barto, §§13.3–13.4</a>; <a href="https://github.com/openai/spinningup/blob/master/spinup/algos/pytorch/ppo/ppo.py">PPO implementation with KL stopping</a>.
