For the past few weeks I've run most of my work through a small company of AI agents. I talk to a supervisor, the supervisor hands each project to a lead, and each lead runs workers that write the code and run the jobs. In one week this setup failed twice, and both times the failure happened at a handoff between two agents. When the pen on my drawing arm ran out of graphite, I asked for a stop. The version that reached the arm, four layers down, said to wait for my explicit word, so the arm stayed still for about 16 hours. In a robotics VLM (vision-language model) benchmark I built overnight with agents, two workers used two different formats for the same point, and the model copied the wrong one. So how should you organize a team of agents, and which model belongs in which seat?

CooperBench is the evidence that a Google DeepMind essay from 29 October cites for "Today's AI systems coordinate poorly in practice". It measures a seam like the one in my benchmark: two agents each build one feature in the same repository, and both features have to pass their tests after the merge. A preprint on teams of coding agents is the only work I found that prices each seat. On its main benchmark, cheap models paid off as planners and hurt as implementers. I couldn't find anyone who has filled in the table at the bottom for today's models on real multi-hour work, which surprises me. Maybe the labs run these comparisons in private for now. Until someone publishes them, I keep tightly coupled work like the arm in one agent. Cheap helpers get bounded jobs that only bring back information, such as searching, reading or running a command.
