This article is a tour of the classical ideas of reinforcement learning. ## Credit assignment

Credit assignment is one of the oldest problems in reinforcement learning. Say you play a whole game and only find out at the end whether you won. Which of your actions deserve the credit, and which the blame? The simplest answer is to discount the reward. If it arrives at step 6, step 5 gets $\gamma$ times that reward, step 4 gets $\gamma^2$ times it, and so on back to step 1. With $\gamma = 0.9$ the numbers in the drawing are just powers of 0.9. You don't need a model of the world for this, only each step's distance from the end. Adding up those discounted rewards from step $t$ gives the return $G_t$.

$$\begin{aligned} G_t = R_{t+1} &+ \gamma R_{t+2} \\ &+ \gamma^2 R_{t+3} + \cdots \end{aligned}$$

A value function stores that number for each state, the return you can expect from there, and so hands a late reward back to the earlier steps.

## Explore or exploit: the bandit

The first reinforcement learning problem most people hear about is the multi-armed bandit. Imagine a casino with ten slot machines, each paying out a hidden average plus some noise. You have 1,000 pulls. How should you spend them to get the most payout?

The Q table here is a single row, because there is a single state, the casino, and ten actions, one for each machine. $Q(a)$ is the average payout of machine $a$ so far, and $n(a)$ counts how often you've pulled it.

$$Q(a) \leftarrow Q(a) + \tfrac{1}{n(a)}\bigl(r - Q(a)\bigr)$$

<div class="algo">
<div class="algo-title">Ten slot machines, 1,000 pulls (ε = 0 is greedy, ε = 0.1 explores a little)</div>
<ol>
<li>Set Q(a) = 0 and n(a) = 0 for each machine a.</li>
<li>Repeat for 1,000 pulls:</li>
<li class="i1">With probability ε pick a random machine. Otherwise pick argmax Q(a), at random on a tie.</li>
<li class="i1">Pull it and observe the payout r. Set n(a) = n(a) + 1.</li>
<li class="i1">Q(a) ← Q(a) + (r − Q(a)) / n(a)</li>
</ol>
</div>

The greedy way to play is the most naive one: always pull the machine that looks best so far. It locks onto its first good-looking machine and never finds out whether another one pays more. So let's add a bit of exploration, and pull a random machine one time in ten. Those random tries correct the numbers.

## Different ways to train the Q function

Every method after this one learns the same thing, a Q function. $Q(s,a)$ is a number for how good it is to take action $a$ in state $s$, and for now you can picture it as a table with one row per state and one column per action. The loop that fills in the table never changes. What changes from method to method is the target in line 3.

<div class="algo">
<div class="algo-title">The loop every method here shares</div>
<ol>
<li>Pick an action a in the state s (greedy, or random with probability ε).</li>
<li>Take it. Observe the reward r and the next state s′.</li>
<li>Build a target for Q(s, a).</li>
<li>Q(s, a) ← Q(s, a) + α · (target − Q(s, a))</li>
</ol>
<div class="algo-note">α is the step size. The methods differ in line 3.</div>
</div>

**[Monte Carlo](http://incompleteideas.net/book/RLbook2020.pdf).** Wait for the episode to end and use the real return as the target. Nothing is guessed, but you learn nothing until the game is over, and some games never end.

$$\text{target} = G_t$$

**[Q-learning](https://www.gatsby.ucl.ac.uk/~dayan/papers/cjch.pdf)** (part 1). Don't wait. Use the reward you just got plus your current best guess for the next state. Updating a guess from another guess is called bootstrapping, and learning from the gap between two guesses made one step apart is called temporal difference (TD) learning. It lets you learn after every single step. The cost is that the table gets too big for most problems, random tries can send you off the cliff in part 1, and a max over noisy numbers runs high.

$$\text{target} = r + \gamma \max_{a'} Q(s',a')$$

**[n-step TD](http://incompleteideas.net/book/RLbook2020.pdf)** (part 2). This sits between the two methods above. Add up the next $n$ real rewards, then let a guess cover the rest. The update for a step has to wait until $n$ rewards have come in. Near the end of an episode fewer than $n$ are left, so you just use the real return you have.

$$\text{target} = R_{t+1} + \dots + \gamma^{n-1}R_{t+n} + \gamma^n V(S_{t+n})$$

**[Sarsa](http://incompleteideas.net/book/RLbook2020.pdf)** (part 4). The name lists what the update uses: State, Action, Reward, next State, next Action. In place of the best next action, it uses the one you actually take next, so the number describes how you really behave, random tries included. The cost is that one unlucky random next action makes the target noisy.

$$\text{target} = r + \gamma\, Q(s',a')$$

**[Expected Sarsa](http://incompleteideas.net/book/RLbook2020.pdf)** (part 4). This removes that noise by averaging over every next action, weighted by how likely the policy $\pi$ is to take it. The cost is that you need the probability of every action.

$$\text{target} = r + \gamma \sum_{a'} \pi(a'\mid s')\,Q(s',a')$$

**[Double Q-learning](https://papers.nips.cc/paper/2010/hash/091d584fced301b442654dd8c23b3fc9-Abstract.html).** The usual explanation for the max running high is that the action that looks best is often the one with the luckiest noise. Double Q-learning keeps two tables. One picks the best next action and the other scores it, so noise in the pick doesn't inflate the score. The cost is that each table learns from half the updates.

$$\text{target} = r + \gamma\, Q_2\big(s', \arg\max_{a'} Q_1(s',a')\big)$$

**[DQN](https://www.nature.com/articles/nature14236)** (part 3). A table gets huge, and you'd like nearby states to share what they learn. DQN replaces the table with a neural network, so similar states get similar values. It also replays old actions and scores $s'$ with a frozen copy of the network. Numbers still run high on some tasks, it needs many samples, and it handles only discrete actions. The target is the Q-learning target, with $Q$ now a network.

## Where the Bellman equation comes from

The Bellman equation says that the value of a state is the reward you get next plus the discounted value of the state you land in. That turns a return over the whole future into a relation between one state and the next, and part 1 turns that relation into an update.

<div class="eq-label">1. The return <span>Eq. 3.8</span></div>

$$\begin{aligned} G_t &= R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots \\ &= \sum_{k=0}^{\infty} \gamma^k R_{t+k+1} \end{aligned}$$

<div class="eq-label">2. Factor out γ <span>Eq. 3.9</span></div>

$$\begin{aligned} G_t &= R_{t+1} + \gamma\bigl(R_{t+2} + \gamma R_{t+3} + \cdots\bigr) \\ &= R_{t+1} + \gamma\, G_{t+1} \end{aligned}$$

<div class="eq-label">3. The episode ends at step T: nothing is left</div>

$$G_T = 0$$

So the value of a terminal state is 0.

<div class="rc-mark" id="sec-bellman2" data-panel="bellman" data-view="bellman2" data-title="Bellman: average, then max"></div>

<div class="eq-label">4. Values are expected returns <span>Eq. 3.12 and 3.13</span></div>

$$\begin{aligned} v_\pi(s) &= \mathbb{E}_\pi\!\left[G_t \mid S_t = s\right] \\ q_\pi(s,a) &= \mathbb{E}_\pi\!\left[G_t \mid S_t = s,\, A_t = a\right] \end{aligned}$$

<div class="eq-label">5. Bellman equation for a policy <span>Eq. 3.14</span></div>

$$v_\pi(s) = \mathbb{E}_\pi\!\left[R_{t+1} + \gamma\, v_\pi(S_{t+1}) \mid S_t = s\right]$$

<div class="eq-label">6. Bellman optimality equation: the average becomes a max <span>Eq. 3.20</span></div>

$$\begin{aligned} q_*(s,a) = \mathbb{E}\Bigl[&R_{t+1} + \gamma \max_{a'} q_*(S_{t+1}, a') \\ &\Bigm| S_t = s,\, A_t = a\Bigr] \end{aligned}$$

Here $S_t$ and $A_t$ are the state and the action at step $t$, $\mathbb{E}$ is the average over the action the policy picks and what the world does next, and $a'$ is any action in the next state $S_{t+1}$.

Equation 5 evaluates a policy you already have. Equation 6 pins down $q_*$, the best possible values. Once you have $q_*$, taking the action with the largest value in each state is an optimal policy, so solving equation 6 solves the problem. The value is not a new reward: $R_{t+1}$ is real, and $\gamma\, v_\pi(S_{t+1})$ stands in for everything after it.

## The deadly triad

Put three of these ideas together and the numbers can blow up: a formula in place of the table, a guess as the target, and learning from old data. Sutton and Barto call this the [deadly triad](http://incompleteideas.net/book/RLbook2020.pdf). DQN has all three, which is why it comes with extra tricks, the replay of old actions and the frozen copy. Part 5 shows how errors amplify.
